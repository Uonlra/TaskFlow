## 2. 优先开发：同步冲突处理

2026-11-18 已实现紧凑冲突入口、双端差异、保留本地副本及采用云端版本，并通过真实双端验收；规则见 [同步冲突恢复](./task-sync-conflicts.md)。后续按下面的验收标准维护。

- 提供一处紧凑的待处理入口，仅在存在冲突时显示数量。
- 点击后展示受影响任务、本地与云端各自新增的关键记录、目标及完成标准差异。
- 首先支持两条明确路径：保存本地版本为独立副本；确认保留云端版本并恢复该任务同步。放弃本地内容前必须已有可恢复副本，或由用户明确确认。
- 使用现有备份重映射规则生成新身份；新副本保留历史，但旧跨任务链接作为备份来源处理，不创建旧目标。
- 处理过程中不暂停其他正常任务的同步。界面打开后若任一端产生新版本，重新核对，不能用过期选择覆盖。
- 冲突不自动合并事件，也不只按更新时间选择一端；网络中断、权限失效与历史分叉分别反馈。

完成标准：两端同时编辑同一任务后，可在界面完成恢复；重试和应用重启不会丢记录、重复建副本或误清队列。正常同步时不增加常驻提示和操作按钮。

实现已覆盖结构化冲突状态与读取接口、紧凑入口和双端差异、保存副本及恢复同步。关系导航与跨入口状态一致性也已在本轮完成，见下一节。

## 3. 关系导航与状态反馈

2026-11-18 已接入按需读取及重试、静态桌面精确节点定位、旧分页外的新任务刷新和日历同账户通知，见 [关联任务入口与页面更新](./task-relations.md)。

- 来源或独立任务已删除、无权限或暂时加载失败时，在关系位置给出对应状态及返回入口；网络失败可以重试，不能误判为已删除。
- 保留历史中的名称与转出事实，不因查询不到目标而清除关系或重新创建任务。
- 检查从总览、日历、工作台、对比页进入同一分支或节点时的定位、返回位置和焦点恢复。
- 补齐真实账户下转出后的列表、分类计数及速览更新检查，避免只更新当前详情。
- 成功反馈保持简短；已保存但刷新失败时只重试读取。

完成标准：删除或无法访问另一端后仍能理解历史、继续使用当前任务；保存后各入口显示同一状态；手机与键盘操作均可走通。

## 4. 长历史与容量

2026-11-18 已建立固定样例和容量验证，并优化校验重放。1000 条样例从约 3.46 秒降至 43 毫秒，测量及后续容量边界见 [性能与容量](./task-evolution-performance.md)。

先测量，依据结果决定优化层级。当前图每批渲染 30 行，但仍读取完整任务快照；渐进显示不等于服务端分页。

- 准备 30、300、1000 条事件以及多分支、长标题、多次采纳的固定样例，记录快照字节数、读取耗时、事件重放耗时、渲染耗时和滚动响应。
- 记录接近当前 1,000,000 UTF-8 字节上限时的保存与导出行为；超限仍必须完整保留原记录。
- 先处理已测得的重复计算、重复渲染或列表瓶颈；若完整快照成为主要瓶颈，再设计“列表摘要、当前状态、事件游标分页”及迁移方案。
- 容量改造必须保留稳定顺序、深链接定位、采纳与撤回引用、导入导出和离线连续历史校验。

完成标准：有可复现的性能基线和优化前后对比；如需拆表，先完成迁移及失败回滚方案，再更换存储方式。

本轮已按顺序推进同步冲突恢复、关系失效与跨入口一致性、长历史性能。后续为生产候选版本整理、发布环境验收及安装升级验证；仍以明确的发布安排为准。服务端事件分页在容量与传输测量需要时另立迁移任务。第一版继续使用主任务、探索分支及执行步骤的层级；多层探索分支、自动成果评分和自动合并目标暂不加入这一轮。
