# 任务详情：探索、结论与采纳

## 当前入口

从任务工作台右侧点击“探索与成果采纳”，或从任务速览进入完整详情。浏览器和桌面端共用同一份详情组件，提交操作通过之前建立的任务仓储保存。

总览与日历速览支持进入指定节点、分支和历史结论，待采纳或待检查提示可以直接打开相应表单；实际保存仍由用户提交。见 [任务演进速览](./task-evolution-overview.md)。

详情顶部以紧凑标题显示当前目标和状态。演进记录位于左侧弹性主区域，右侧约 300px 的操作栏集中显示任务描述、完成标准、探索分支、成果与操作表单。演进区使用更明确的标题和选中态，操作栏采用较淡背景与克制的按钮层级。默认选中最近创建的分支；没有演进历史时，主区域显示已有任务活动。

任务属性、标签与编辑、删除入口收在右上角“任务信息”面板，支持点击外部或按 Escape 收起。较长的右侧内容可独立滚动，提交表单不替换演进图；点击节点后，记录区域适当收缩，在下方展示详情。可用宽度不足 820px 时切换为上下布局，并优先显示演进记录；手机端分支导航横向滚动，属性面板从底部展开并避开固定导航。

## 操作流程

1. **创建探索分支**：填写方案名称和验证问题。从当前主目标派生分支，旧任务首次操作时才建立演进起点。
2. **推进探索**：在选定分支记录进展、添加与完成步骤，或通过“调整探索状态”开始、结束、搁置及恢复方案。
3. **提交结论**：填写摘要，将可分别采纳的成果按每行一项输入。每次提交建立一个独立的成果版本，历史结论保持不变。
4. **纳入主线**：选择一个结论中的具体成果条目，填写选择理由，并确认保存后的目标和完成标准。表单展示目标前后对比，确认后一次保存主任务和采纳记录。
5. **继续决策**：部分采纳后，其余成果仍保留；再次采纳时已采纳的条目不可重复选择。采纳本身不结束分支。

主目标或完成标准改变后，相关分支显示“待检查”。检查时展示此前依据的目标与当前目标，填写原因后才能继续推进或采纳该分支。已结束或搁置的分支仍保留成果。

## 目标、历史与验收

“调整目标”记录目标、完成标准及变更原因。已有演进历史的任务在普通编辑表单中将标题设为只读、状态设为不可修改，仍可以调整备注、标签、日期和优先级。

演进记录使用 Git 式图与事件列表，最新记录在上，主线固定在左，探索分支向右展开。默认突出关键事件，连续的进展与步骤收为可展开的提示行；也可切换查看全部。每批显示 30 行，继续显示更早记录时保留图的真实关系。点击节点或事件查看原因、来源、实际采纳内容和目标变化，可定位来源结论、来源分支，以及撤回记录对应的原采纳。采纳记录可撤回，撤回时必须确认接下来使用的目标，并保留原始记录及汇入线。

“突出分支”只弱化其他路径，保留主线与上下文。方向键上下移动记录，Home/End 到达当前首尾，向右进入节点详情，Escape 关闭详情并恢复记录焦点。窄屏切换为带来源分支的纵向时间线。完整规则见 [Git 式演进图](./task-evolution-graph.md)。

填写完成标准，并结束或搁置所有仍在推进的分支后，“验收完成”才可用。填写验收说明后保存完成状态；完成后可填写原因重新打开任务。

## 保存与刷新

- 表单记住打开时的版本。保存失败保留草稿，原样重试使用同一操作标识，避免重复采纳。
- 保存期间锁定表单，防止重复提交。若任务已有新记录，保留草稿并提示检查；不自动将旧草稿套用到新版本。
- 错误后可重新加载任务。加载不会自动替换正在编辑的草稿；关闭表单并重新操作，才使用新版本作为依据。
- 保存结果立即更新详情标题、属性和成果列表。晚到的旧读取响应不能覆盖新内容。
- 从详情修改尚未出现在 Store 分页集合中的任务时，也会保留服务端返回的新任务，确保后续普通属性编辑正确显示。

## 验证及后续范围

已通过界面测试覆盖创建分支、结论、部分与再次采纳、失败重试、重复提交、过期草稿、目标检查、验收和撤回。浏览器已实际执行创建分支、提交两项成果、部分采纳并更新目标，刷新后验证记录恢复；390px 窄屏检查没有页面横向溢出。

详情页已接入 Git 式演进图，并通过样例实际检查旧成果多次采纳、定位具体结论版本、主题及移动端布局。完整方案比较视图、分支转独立任务与总览速览的演进摘要仍按推进计划后续接入。云端环境仍需先完成 [持久化说明](./task-evolution-persistence.md) 中的迁移及真实账户验收，当前真实浏览器流程使用访客存储。
