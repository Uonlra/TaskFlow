# 任务探索与演进：实施计划

状态：实施中。已交付领域规则、持久化与同步代码，并接入任务详情页的探索、提交结论、采纳操作及 Git 式演进图。总览速览已接入目标、待处理提示、最近演进和记录进展；完整方案比较及工作台关系摘要仍待推进，云端迁移与真实账户验收待目标环境执行。本文是后续开发与验收基准。

当前代码与行为约定见 [任务演进领域约定](./task-evolution-domain.md)。

## 1. 已确认的产品范围

- 主任务保存当前目标和完成标准，探索分支代表不同方案。
- 第一版只允许主任务创建探索分支；分支内部支持执行步骤。
- 分支支持记录进展、提交结论、搁置和结束；探索状态与成果采纳状态分开。
- 成果可以部分采纳，也可以分多次采纳；采纳不自动结束分支。
- 采纳时由用户确认主任务修改，将成果引用、修改前后内容和选择原因一起保存。
- 主目标变化后，已有分支保留原来的目标依据，并提示检查。
- 主任务按当前完成标准验收；完成前处理未结束分支，可结束、搁置或转为独立任务。
- 支持撤回采纳，保留记录；存在后续修改时不能直接覆盖当前目标。
- 沿用项目现有主题，采用细线、留白、克制配色，普通进展默认折叠。
- 总览点击任务仍打开速览，突出当前目标、待处理成果和最近演进。

## 2. 阶段一：数据与行为设计

交付：任务领域类型、操作约定、数据迁移方案及测试场景。

- 定义主任务、探索分支、执行步骤、目标版本、进展、成果版本及演进事件之间的关系。
- 分支记录创建依据，采纳记录引用具体成果版本；后续编辑不能改变已发生的采纳事实。
- 为新操作定义稳定操作 ID、版本检查、失败重试和撤回规则。
- 区分普通文字修正与正式目标调整，明确哪些操作触发分支检查。
- 历史任务只迁移现有可确认的信息；旧时间戳不转换为虚构的进展或目标变更。
- 确定列表、日历、总览统计口径：默认以主任务及独立任务计数，执行步骤和探索分支单独摘要，避免重复计数。
- 确定复制、删除、转独立任务及导入导出时的关系和历史保留方式。

验收：用“并行方案、部分采纳、多次采纳、目标调整、撤回、任务收尾”示例验证状态和记录可以完整表达。

## 3. 阶段二：持久化与同步

依赖：阶段一。

交付：浏览器本地、桌面 SQLite、云端接口及其迁移与同步能力。

- 扩展现有任务仓储边界，增加探索、记录进展、提交结论、采纳、目标调整和收尾等操作。
- 浏览器本地存储增加版本迁移，SQLite 增加可重复执行的迁移，云端提供表结构与索引准备脚本。
- 核对当前 Appwrite 版本支持的事务能力，选定能保证主任务更新与采纳记录完整保存的方案。
- SQLite 在同一事务中更新任务、写入事件和加入同步队列；其他存储采用相应的一致性机制。
- 同步覆盖新实体、关系、事件和删除标记；处理重复请求、离线补传及多端同时修改。
- 明确版本冲突反馈，防止旧目标或旧成果静默覆盖较新的内容。
- 升级导入导出格式，保留关系与历史，继续兼容原有任务备份。

验收：重启后数据完整；重复提交不重复采纳；模拟失败不会留下半次操作；离线恢复后关系与事件保持一致；旧数据可正常使用。

## 4. 阶段三：完整任务操作流程

依赖：阶段二。

交付：能实际使用的任务详情页与操作表单。

- 展示当前目标和完成标准，支持正式调整目标及填写原因。
- 创建探索分支、维护执行步骤、记录进展、提交带版本的成果结论。
- 提供方案比较，展示验证问题、成果、成本与限制；不自动代替用户选择。
- 实现“选择成果 → 确认主任务修改 → 查看摘要 → 保存”的采纳流程。
- 显示哪些成果已采纳；多次采纳时可识别新增内容，避免重复纳入。
- 支持检查过期分支、撤回采纳、搁置或恢复探索、转为独立任务与完成验收。
- 新操作统一反馈保存结果，保存成功但刷新失败时提供刷新重试，避免重复保存。

验收：通过真实界面走通“创建目标 → 并行探索 → 记录结论 → 部分采纳 → 调整目标 → 再次采纳 → 完成验收”。

## 5. 阶段四：简洁的 Git 式演进图

依赖：阶段三的真实事件数据。

交付：可复用的完整演进图和紧凑预览。

- 采用最新在上的事件列表，主线固定在左，探索分支向右展开。
- 节点与事件行对齐；成果汇入使用双圈节点，搁置采用文字和图标，颜色只辅助区分路径。
- 连线依据真实的分支起点和采纳关系生成；搁置或结束不绘制虚假的汇入线。
- 支持同一分支多次汇入主线及采纳后的继续探索。
- 默认突出关键事件，普通进展可展开；过滤或折叠时保留必要的连接提示。
- 点击节点查看详情，汇入事件突出实际变化；支持键盘操作，信息不依赖悬停或颜色。
- 长历史按需加载，时间相同的事件仍保持稳定顺序；移动端使用紧凑纵向布局。

验收：并行、交错、搁置、多次汇入、长标题、长历史及窄屏下均能正确读出关系；截图检查节点和连线对齐。

## 6. 阶段五：总览速览与工作台接入

依赖：阶段三、四。

交付：总览、任务列表、速览和详情页之间一致的体验。

- 总览原列表点击打开速览，关闭时恢复焦点和原浏览位置。
- 速览按“当前目标 → 一条优先待处理提示 → 探索摘要 → 最近 3～5 个关键节点”组织。
- 只有用户明确提交待决策结论，才显示待采纳提示；分支待检查也提供直达入口。
- 速览支持记录进展，节点详情就地展开；比较方案、采纳与目标调整进入完整详情并定位。
- 任务工作台支持查看探索摘要、展开关系和进入对应任务。
- 无分支任务隐藏空图、零计数与多余入口；次要属性和操作收入“更多”。
- 统一保存后的缓存刷新，使总览、列表、速览、详情、日历及统计遵循同一口径。

验收：从总览打开任务、记录进展、进入对应分支、采纳成果、返回总览后内容一致；完成操作无法绕过分支收尾规则。

验收：端到端流程通过；数据一致性与迁移检查通过；真实运行界面符合已确认的简洁方向。
