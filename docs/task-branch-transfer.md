# 探索分支转为独立任务

在完整详情中选择方案，点击“转为独立任务”，确认新任务目标、完成标准和转出原因后保存。目标默认使用方案名称，完成标准需要单独填写。目标依据过期时先检查分支；已完成的主任务需要先重新打开。

## 转出后的行为

- 原任务的目标和完成标准保持不变。分支显示“已独立”，保留进展、步骤、全部结论和采纳记录，停止继续推进、恢复和新增采纳。
- 新任务以“进行中”建立，使用独立确认的目标与完成标准；描述取自原验证问题，优先级及其他属性使用新任务默认值。执行步骤和旧结论仍保留在来源分支，不伪造为新任务已执行的记录。
- 原分支和转出节点提供新任务入口；新任务显示来源任务与分支名称，可返回原转出节点。来源名称保存转出时的快照，后续改名不会改写历史。
- 演进图在分支路径上显示转出箭头，不绘制成果汇入主线的连线。对比视图和工作台关系中显示“已独立”，替换原采纳操作。
- 转出的方案不再计入进行中的探索或待采纳事项。新任务作为一个正常任务计数，其完成状态不阻止原任务按自身标准验收。
- 已发生的采纳仍属于原任务，撤回历史采纳沿用原有规则；不会修改新任务目标。转出记录本身不提供撤销或自动重新合并。

## 保存、重试与同步

命令携带固定操作 ID、新任务 UUID 和原任务版本。普通单任务演进入口拒绝单独写入转出命令；专用仓储同时保存来源与新任务。表单保存失败保留草稿和标识，原样重试不会重复建任务。过期版本、已转出分支、目标未检查或目标标识冲突会停止保存。

- **访客模式**：两份任务一起写入现有 `sessionStorage`。写入失败时，任务集合和历史都不更新；刷新可恢复，临时存储规则与原有访客模式相同。
- **桌面端**：两份任务、来源事件及两条同步快照在同一个 SQLite 事务中写入。写入后续队列失败会回滚已创建的新任务。旧桌面桥接会提示升级。
- **云端**：认证接口 `POST /api/tasks/:id/transfer` 使用用户会话和行权限。先对来源建立写冲突检测，再在同一事务中暂存新任务和转出记录，最后一起提交；遵循 [Appwrite 事务机制](https://appwrite.io/docs/products/databases/tablesdb/transactions)。目标创建失败或并发冲突时回滚。提交成功但响应丢失时，重试读取既有结果；新任务后来被删除时不会再次创建。
- **离线补传**：合并后的队列先按来源关系排序，再按数量和容量分批，避免子任务排在来源之后的队列批次长期无法发送。云端接收新增转出事件时，在保存来源快照的同一事务中建立新任务的初始版本；新任务后续进展再沿用原有快照同步。来源冲突会保留本地队列，目标快照需要与已提交的来源记录匹配。

## 备份与来源失效

导出保留来源、转出命令和历史。作为新身份导入时，历史跨任务链接标记为备份关系：仍可查看名称和转出事实，但不指向原工作区的旧任务，也不重新创建旧目标。导入后的任务仍可以把其他分支转出，新发生的关系正常生效。

来源或目标任务被删除后，不自动级联删除、复活或解除另一份任务；剩余任务可以继续使用，历史保留当时的名称，原链接按现有详情的不存在/权限状态处理。

## 验证及交付边界

领域和仓储测试覆盖历史重放、版本冲突、分支检查、原分支只读、重复重试、目标冲突、来源校验、备份关系、队列排序与失败回滚。SQLite 测试包含关闭数据库后重开；云端事务模拟包含提交响应丢失场景。浏览器已检查访客来源定位、独立进展及刷新恢复。2026-11-18 另已通过真实 Appwrite、两份用户会话与桌面冷启动补传验收，见 [验收记录](./task-evolution-validation.md)。

本机配置指向的云端环境已准备任务演进字段，本次没有部署 API 或发布安装包。网页 API、同步服务与桌面应用需要使用支持本次命令的版本；其他目标环境仍需按 [持久化说明](./task-evolution-persistence.md) 独立完成迁移检查和真实账户双端同步验收。
