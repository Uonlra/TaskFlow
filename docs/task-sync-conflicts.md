# 同步冲突恢复

任务历史分叉后，桌面端保留本地记录与待上传操作，在全局显示一处“同步待处理”入口。没有冲突时不显示入口。点击后重新读取云端，比较两端目标、完成标准及各自新增的记录；默认展示最近五条，可展开全部新增记录。

## 两种处理方式

- **保留本地副本并恢复同步**：在同一 SQLite 事务中建立带“本地副本”标签的新任务，保留本地目标、历史和属性；原任务采用已核对的云端版本。副本使用新 ID，历史跨任务链接按备份来源处理，避免创建旧目标。
- **采用云端版本**：先显示确认步骤；用户明确确认后，才替换原任务尚未同步的本地修改。不自动创建副本。

云端已经删除的任务可以作为删除版本处理，不会因恢复操作复活。若本地还有云端未提交过的转出子任务，这些任务保留自己的记录，来源关系冻结为备份来源，继续作为独立记录同步。

## 保存与版本约束

冲突状态、恢复结果回执保存在新增的本地表中，数据库启动时自动执行可重复迁移。单次恢复同时保存副本、替换原任务、更新关联离线任务、清理原队列及写入回执；任一步失败则整体回滚。

恢复前核对最新本地操作 ID，并重新读取云端。任一端改变后，旧选择不能直接保存，界面需要重新查看。请求携带稳定恢复 ID 和副本 ID；回执可以处理响应丢失后的重试，应用重启后也不会重复创建副本。

有冲突的任务及依赖其未提交转出记录的后继任务暂不上传。筛选发生在数量限制之前，其他正常任务继续同步。网络、认证或权限失败不会被误记为历史分叉；读取失败时保留本地内容，禁用未经核对的恢复操作。

冲突恢复是显式替换分叉历史的专用入口；普通保存、远端导入及队列确认仍维持原有连续历史检查。旧桌面桥接不提供恢复功能时，不开放处理操作。

## 验证

- SQLite：冲突与回执重开恢复、原样重试、过期本地及云端选择拒绝、事务失败回滚、删除确认、关联离线任务保留及正常任务绕过阻塞组。
- 应用：结构化冲突快照、读取权限、失败重试标识、二次确认、全部新增记录展开及详情页从较长本地分叉切换到较短云端历史。
- 真实云端与源码桌面：11 组验收通过，覆盖冲突冷启动恢复、正常任务继续同步、界面保留副本及明确采用云端版本。报告为 `test-results/evolution-cloud-1794988549389/report.json`，本轮 4 份任务已清理。
- 界面：浅色、深色、390px 布局；对比区可聚焦滚动，页尾操作保持可见。
