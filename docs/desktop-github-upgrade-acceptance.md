## 后续发布工作

当前可以继续使用公开 beta.2。若下一目标为稳定版，需要先确认版本、签名策略及未完成验收项目的处理，再推进下列工作：

1. 调整 `.github/workflows/desktop-beta.yml`：当前仅接受 beta 标签、创建 prerelease，上传的通道文件固定为 `beta.yml`；稳定版需要独立配置 `latest` 通道和非 prerelease 草稿。
2. 调整 `scripts/verify-desktop-release.mjs`：目前版本正则、元数据及发布配置断言只接受 beta；同时调整 `scripts/verify-published-desktop.mjs` 的 beta 专用断言。增加通道隔离与错误版本拒绝检查。
3. 核对 package.json 中固定的 `publish.channel: beta`、发布说明与构建配置；仅修改版本号不足以得到可发布的稳定版。
4. 构建稳定版候选，审核草稿及文件校验；验证 beta.2 能迁移到稳定版、稳定版使用 `latest` 且不接收 beta。当前 beta.1 → beta.2 的结果不能替代这项验证。
5. 用户审查并确认公开发布；公开后再验证最新通道、实际升级及文件下载。若保留未签名发布，需要明确用户对稳定版签名策略的选择。

本次记录不变更版本号、安装程序、Appwrite 数据结构或已公开标签，也不等同于稳定版发布批准。
