# Windows 安装与数据保留验收

运行环境：Windows x64。验收脚本使用当前源码和已生成的桌面静态资源，构建两个仅供测试的 NSIS 安装包（2.1.1、2.1.2）。它们使用相同的独立应用标识，以验证覆盖升级；标识、产品名、包名均与正式 TaskFlow 隔离。

## 运行方法

```powershell
pnpm desktop:web-build
pnpm desktop:smoke:install
```

脚本需要 `dist/electron-cache/electron-v<版本>-win32-x64.zip` 中与 `package.json` Electron 版本匹配的官方发行包。安装包构建使用 `--publish never`，不会上传到 GitHub，不会修改正式版本号。

每次运行在 `dist/install-acceptance/run-<时间戳>` 下生成安装包、安装目录和 `report.json`。程序使用独立产品名对应的**默认** Windows 应用数据目录，不通过 `--user-data-dir` 绕开卸载逻辑。关闭真实网络访问，不使用真实账号。

若构建已经完成而验收中途失败，可使用 `pnpm desktop:smoke:install --resume=<时间戳>` 复用该次安装包。脚本校验测试包的独立标识；已有测试数据会先重命名保留，再从干净数据重跑。此模式不会重新构建安装包，修改应用源码后应重新执行完整命令。

## 验收内容

1. 静默安装 2.1.1，校验安装后的可执行文件版本，实际启动程序创建任务。
2. 保存模拟身份、账户工作区和待同步操作，暂停同步并将任务改为完成。
3. 正常退出，覆盖安装 2.1.2，校验版本确实更新、安装阶段未修改数据文件；启动后读取原任务、完成状态、加密身份、工作区及队列。
4. 使用安装生成的卸载程序执行默认卸载，确认程序已移除。比较数据库、数据库密钥、`Local State` 和身份文件的 SHA-256，要求全部保留且内容一致。
5. 重新安装 2.1.2，实际启动、解密数据库并恢复上述内容。
6. 最后卸载测试程序，保留独立测试数据和报告，便于复查。若中途失败，保留当次测试安装供排查。

生产配置明确设置 `nsis.deleteAppDataOnUninstall: false`。这代表默认卸载保留数据；显式要求清除应用数据的卸载不在本次范围内。

## 范围与后续人工验收

两个测试版本使用同一份源码，验证的是安装替换和数据保留机制，**不验证旧发布版数据库结构迁移**。测试禁用桌面和开始菜单快捷方式及安装完成后自动启动，避免干扰日常环境；其余沿用当前安装配置。报告通过也不能替代以下检查：

- 正式应用标识下，从实际旧版本覆盖到候选版本，验证真实数据库迁移；应先导出备份，并在独立 Windows 用户或虚拟机中完成。
- 正式安装向导、目录选择、快捷方式和卸载入口。
- 正式安装包签名及 Windows 安全提示体验。
- 自动更新下载安装的完整链路；本次通过手动运行安装包模拟升级。

加密数据依赖当前 Windows 用户的系统安全存储。保留数据库文件并不等于支持换电脑或换 Windows 用户直接恢复；跨设备迁移应使用任务页 JSON 导出、导入。
