# 工作台：探索摘要与关系入口

任务列表继续按主任务计数。有探索分支的任务在标题下显示方案数，以及一项优先提示：先显示待检查分支数，否则显示仍有未采纳成果的结论份数。该行替代任务描述，保持列表行高和原有筛选、排序口径。没有分支时保留原有描述，不显示空摘要；完成的任务不显示待处理提示。

点击摘要按钮选择对应任务，并在右侧展开探索关系、聚焦展开按钮。普通任务行仍只切换详情。关系在当前列表中展开，不额外读取每个分支，也不把分支插入任务列表。移动端复用同一摘要，点击任务或带演进历史任务的完成按钮进入完整详情。

切换“详情”和“活动”时保留关系的展开状态，键盘焦点继续留在所选页签；重新选择其他任务时使用该任务的独立详情状态。

## 右侧内容

- 显示当前完成标准和可折叠的探索摘要。进行中数量只包括待探索、探索中的分支。
- 默认只显示一条待处理链接，规则与总览速览一致。
- 展开后显示主线及其直接派生的方案，列出探索状态、真实结论数和当前有效采纳的条目数；已撤回采纳不计入，未提交的内容不作为结论。
- 分支名称定位该分支的起点事件及右侧方案内容。采纳链接定位最新一份含有可用成果的具体结论版本，打开确认表单，不直接保存。
- 目标依据过期时先进入分支检查；已搁置方案不直接提供采纳入口；已结束方案仍可采纳；完成任务保留关系和历史入口，隐藏决策操作。
- “活动”页签使用最近五个关键演进节点，支持继续查看更早记录、就地打开节点及定位完整详情中的原记录。右栏的记录行省略日期，节点详情与可访问名称保留完整时间。没有实际演进事件时沿用可确认的创建、更新和完成时间。

关系较多时在右栏内部滚动。键盘可以激活列表摘要、展开关系、访问分支和决策链接；行内操作不会额外触发任务行选择。普通任务保留原有完成操作，带演进历史的任务在详情中执行验收或重新打开，沿用已有领域规则。

## 数据与验证

摘要使用现有任务分页返回的完整任务及演进快照，访客和桌面端沿用 Store 数据，不增加逐行网络读取或数据库字段。详情中保存后，返回工作台时列表和关系使用更新后的任务数据。登录模式下，同一账户已保存的新演进版本会先覆盖旧摘要，并按版本刷新一次分页，重新核对筛选结果、排序和分类计数。刷新失败保留已保存内容并提供现有重试入口，不自动重复请求同一版本；其他账户的 Store 快照不会参与合并。展开关系只改变当前界面状态，不生成演进事件。

测试覆盖摘要优先级、真实计数、历史结论定位、撤回排除、搁置/结束/完成状态、键盘事件边界、指定任务关系展开和原有详情兼容。访客浏览器已走通“工作台进入指定结论 → 采纳 → 返回后摘要更新”，并检查分支起点、分支检查和演进记录定位。390px 移动列表与 1280px 工作台均保持页面宽度。

本次不增加分支转独立任务或跨任务依赖关系；云端迁移与真实账户双端同步仍按 [持久化说明](./task-evolution-persistence.md) 验收。
